---

The sections below are **optional** but recommended. Existing skills remain valid without them; new skills benefit from them. Add them when a skill is refined past its first draft.

## Expected Outcome *(optional)*

What success looks like when this skill runs correctly. A concrete, checkable signal — not a vague goal. Helps future sessions tell a clean run from a broken one.

## Troubleshooting *(optional)*

Common failure modes and fixes. Format: `Issue: X. Solution: Y.` Add an entry each time a session uncovers a new way the skill can fail.

## Red Flags *(optional)*

Warning signs the skill is being applied wrong or rushed. Two useful shapes:

- **"You're rushing"** — shortcuts that look efficient but lose signal
- **"You're wasting tokens"** — expensive patterns a cheaper alternative covers

## Lessons Log *(optional)*

Dated table that updates as the skill is used. This is the compounding mechanism — a skill without one degrades; a skill with one gets sharper every session.

| Date | Lesson | Change Made |
|------|--------|-------------|
| YYYY-MM-DD | What went wrong or what worked better | What you changed in this file |

Only add a row when a session teaches something non-obvious. Empty for a long stretch is correct — over-logging is noise.
